# 小小记账

一个简体中文、无依赖、无需构建的私人记账 PWA，使用原生 ES 模块。账目和预算只保存在当前浏览器的 localStorage 中，不注册账号、不上传数据、不使用 CDN。首次联网打开并完成缓存后，可以离线记账。

## 本地运行

在本目录启动静态服务器：

```sh
python3 -m http.server 8000
```

用浏览器打开 `http://localhost:8000`。ES 模块需要通过 HTTP(S) 加载，不能直接双击 `index.html`。

## 使用

底部导航包含四个页面：

- **首页**：今天还能花、今日建议、本月净消费、收入、预计储蓄和最近五笔记录。
- **记一笔**：输入金额、日期和可选备注，选择支出、收入、退款或转账，再点分类保存。退款应选原消费分类。
- **明细**：默认显示当前月，可通过月份选择器或左右按钮切月；记录按日期分组，标注手动／微信／支付宝来源。可编辑记录，删除前会确认。分类条形图展示净消费金额和占比，支出减退款，收入和转账不参与。
- **设置**：月度预算、微信／支付宝 CSV 导入预览、JSON 备份与恢复。

占比按分类净消费除以当月净消费计算。分类退款超过支出时，分类金额和占比可以为负，其他分类占比可能超过 100%；条形长度按分类净额的绝对值缩放。合计净消费为零或负数时，占比显示为「—」。导入的分类为关键词推测，可在明细中修正。

## 部署到 GitHub Pages 或静态 HTTPS 服务

1. 将本目录的全部应用文件提交到 GitHub 仓库，保留 `index.html`、`js/`、样式、图标、`manifest.webmanifest` 和 `sw.js` 的相对位置。
2. 如果应用文件位于仓库根目录，在仓库 **Settings → Pages → Build and deployment** 选择 **Deploy from a branch**，选择分支及 **/(root)**，保存。若应用位于子目录，可将其内容放到所选发布目录，或用 Pages 工作流发布该目录。
3. 等待部署完成，用 Pages 提供的 HTTPS 地址打开。项目子路径也可使用，资源均为相对路径。

也可以把这些静态文件原样上传到任意静态 HTTPS 托管服务，无需后端、数据库或构建命令。配置说明见 [GitHub Pages 官方文档](https://docs.github.com/zh/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## 添加到 Android 主屏幕

1. 在 Chrome 中打开部署后的 HTTPS 地址，首次使用时保持联网，等待页面加载完成。
2. 点击 Chrome 右上角菜单 **⋮ → 添加到主屏幕／安装应用**，按提示确认。不同版本的菜单名称可能略有差异，见 [Chrome 安装说明](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=zh-Hans)。
3. 之后可以从主屏幕打开，缓存完成后也能离线使用。

PWA 安装和 Service Worker 需要 **HTTPS 或 localhost**。手机访问电脑的普通局域网 HTTP 地址不满足安装条件。微信内置浏览器不能安装 PWA，请选择「在浏览器打开」，使用 Chrome／系统浏览器；Android 推荐 Chrome。

## 导出和导入账单

### 微信支付

在微信中进入 **我 → 服务 → 钱包 → 账单 → 常见问题 → 下载账单**。选择用于个人对账的账单，按提示选择时间范围和接收邮箱。部分微信版本把下载入口放在账单页右上角的菜单中。

从邮箱下载账单压缩包，按微信提示获取密码并解压，取出原始 `.csv` 文件。在小小记账 **设置 → 导入账单** 选择「微信支付」并选择该文件。

### 支付宝

在支付宝中进入 **我的 → 账单 → 右上角「…」→ 开具交易流水证明／下载账单**，选择 **用于个人对账**，设置日期范围和接收邮箱。下载邮件附件，按支付宝通知中的密码解压，取出 CSV 文件。入口名称随版本变化，可在支付宝客服中搜索「下载账单」；不要选择仅提供 PDF 的证明用途。可参考 [支付宝手机端账单导出图文步骤](https://docs.qianjiapp.com/other/import_guide_alipay_app.html)。

在小小记账 **设置 → 导入账单** 选择「支付宝」，再选择解压后的 CSV 文件。应用支持 UTF-8 和 GBK 编码、表头前说明行、带引号的逗号字段及末尾空格／制表符，无需用 Excel 另存。

### 确认导入

选择文件后会显示有效记录数量、**新增／重复** 数量，以及前五笔新增记录。点击 **确认导入** 才会保存，取消不会改变账目。

- 支出 → 支出；收入 → 收入；不计收支、`/` 或空白 → 转账，不参与收支统计。
- 交易类型或状态包含「退款」时，按退款处理，抵扣对应分类消费。
- 交易关闭、失败的记录会跳过。
- 按 **日期 + 时间 + 两位小数金额 + 交易对方** 去重，同时检查现有账目和文件内重复；重复导入同一文件不会重复入账。该规则不使用订单号，完全同时间、同金额、同对方的不同交易也会被视为重复，请核对预览。
- 导入记录保留来源和交易对方。分类按关键词推测，退款分类不准确时，请在明细中改成原消费分类。

这里只读取 CSV，不直接读取 ZIP、Excel 或 PDF，也不连接微信／支付宝账户。

## 备份、恢复和本地数据

在 **设置 → 备份与恢复 → 导出 JSON 备份** 下载文件。备份包含 `version`、全部 `transactions` 和预算 `settings`。请定期备份，尤其是在清除浏览器数据、更换手机、切换浏览器或更换部署网址之前。

选择 JSON 文件恢复时，会先校验版本、交易字段、金额、日期、时间、来源、唯一 ID 和预算结构，再询问是否覆盖。确认后，**全部现有记录和预算会被备份替换**，不会合并；取消或校验失败不会修改当前数据。建议恢复前先导出当前备份。

数据不会自动跨设备同步。浏览器清理、隐私模式结束或存储被系统回收，都可能导致数据丢失；不同浏览器、网址或端口的存储也可能不同。JSON 备份包含账目明文，请自行妥善保管。示例账单只存在于 `tests/fixtures/`，不会自动写入应用。

## 预算规则

`js/budget.js` 提供纯函数 `computeDashboard(transactions, settings, todayDateString)`，不访问 DOM、存储或系统时间。金额先转为分汇总，日建议保留计算精度，展示时保留两位小数。

- 可花预算 = 设置月收入 − 固定支出 − 储蓄目标 − 备用金。
- 今日建议 =（可花预算 − 本月今天之前的净消费）÷ 本月剩余天数，含今天。
- 今日剩余 = 今日建议 − 今日净消费，超支允许负数并显示红色。
- 净消费 = 支出 − 退款；转账不计入消费或收入。
- 本月预计能攒 = 设置月收入 − 固定支出 − 备用金 − 本月净消费，允许负数。

固定支出已作为预算预扣项，请勿重复记为日常消费。本月收入卡显示实际记录的收入，不改变按设置月收入计算的预算。账目按本地日历日期统计；未来日期记录计入对应月份，但不影响今天之前的预算分配。

## 开发与测试

无需安装依赖，使用 Node.js 22.7+：

```sh
node --test tests/*.mjs
```

测试覆盖预算进位和月末／闰年、退款抵扣、转账排除、超支、微信／支付宝解析、UTF-8／GBK 解码、去重、编辑删除、备份校验、存储失败及离线资源。所有账单样本均标注「示例数据 / example data」，使用虚构商户与订单号。

GBK 样本已随仓库提供；如需重新生成，运行无依赖的脚本：

```sh
node tests/fixtures/generate-gbk.mjs
```

`js/importers.js` 导出纯解析器 `parseWechatCsv`、`parseAlipayCsv`、解码器 `decodeBillBuffer`、`dedupKey` 和 `mergeTransactions`。合并函数返回 `{ added, skipped }`：`added` 是新增记录数组，`skipped` 是重复记录数量，不修改输入或存储。

新增离线资源时，需要更新 `sw.js` 的 `SHELL` 列表并递增缓存版本。当前为 `little-ledger-shell-v4`，激活时清理旧版本缓存，保留其他应用的缓存。

## Android APK v0.3.0

原生 Android 工程 [`android/`](android/README.md)，应用名「小凪记账」。支持通过无障碍识别微信／支付宝可见的支付、转账与微信红包页面、微信支付凭证，通知作为补充；两个渠道共享三分钟去重，返回应用后自动入账并显示「自动」。首次引导提供无障碍设置入口、开启状态与本机隐私说明，应用没有联网权限。浏览器版不依赖 AndroidBridge，使用方式保持不变。构建步骤、解析与去重规则、测试和手机设置详见 Android 说明。
